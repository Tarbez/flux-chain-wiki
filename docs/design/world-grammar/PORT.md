# Porting the whole site off Three.js

For the owner and the lanes doing the port. Owner's words (2026-10-30): "Port each remaining view's 3D into the grammar renderer. Port the NFT card and the skins. Make the grammar world the default, ready to drop threejs entirely."

## Where things stand

The grammar world (`js/world2/`, records in `world/world.flx`, encoder `scripts/world-encode.mjs`) is the default world and draws every route the four batches ported (see Progress). Three.js runs only under `?world=1`, for the audit. One file, `js/world2/world-choice.js`, makes that choice. Three.js (`js/vendor/three-r180-defxn.js`, 724 KB) still draws the other 20 views through `js/world/*.js` (21 files), and three more users load it: `js/nft/art3d.js`, `js/nft/card.js`, `js/ark/skin-site.js`.

## The rule for every view

A view is ported when all of these hold, measured, never eyeballed:

1. Same camera: for each route, the grammar view's camera (aim, distance, elevation, yaw, lens) equals the Three.js view's at rest, to 1e-3.
2. Same picture: a side-by-side screenshot pair at 1440x900 for each route, plus a pixel-difference score, reviewed by a person. The lane reports the pair, not a verdict.
3. Same contract: every page hook the view uses still works (`ArkWorldHost.state`, `select`, `on('pick' | 'pickRing' | 'hover' | 'stagePick' | 'open')`, `tags`), checked by a script per route.
4. Same or better speed: first frame and frame median not worse than Three.js on the same machine and run.
5. 0 page errors.

## How a view is made

Derive, don't author. The encoder runs each stage file's placement maths once, at build time, and writes:

- the view's camera as a `WVIEW` record;
- its settled frame as a content-addressed blob (the instance format in CONTRACT.md);
- its motion (pieces moving in and out, the camera flight) as animation records sampled by the one sampler (`fxn-3d/scripts/lib/anim-sample.mjs`), never per-view JavaScript;
- its labels (`tags`) as records the host places.

The browser host flies between views, plays the motion and answers the hooks. No view keeps its own drawing code.

## Order

1. Map: every view, its stage file, what it draws (parts, counts), what state it reads, which hooks its page uses, and what it animates. The NFT card and the skins, mapped the same way. A parity harness that screenshots one route under both worlds.
2. Port the views in batches by kind: chain views; identity views; how-it-works views; stats, resolvers, FXN, ring, trace, download, kit.
3. Port the NFT card and the skins.
4. Make the grammar world the default; Three.js stays reachable only by `?world=1` while the audit runs.
5. Final audit of every route against the rule above, then remove Three.js and its files, and prove the site still loads every route with 0 errors.

## Laws

No JSON on any wire or store, no WASM, no libraries, derive don't author, one grammar per thing, one renderer, one sampler, draw on demand, never regress speed, commit nothing until the owner asks, tests lock only what the owner has confirmed. At most 4 agents at once.
