# The first hour with DEFXN, screen by screen

Reader: the owner and the next agent who touches the site's first-run screens. This page maps what a newcomer meets from the first visit to a signed-in account. It lists the gaps, the fixes made on 2026-10-24, and what the browser session must change.

Checked on http://127.0.0.1:4640 at 1280x720 and 1440x900. Screenshots are in `/private/tmp/claude-501/-Volumes-PortableSSD-flux-defxn/0413e07e-be2f-4f97-831d-5e0f918ebaa8/scratchpad/journey/`. Nothing is live (devnet), so no screen may show live numbers, users or a "Live" tag.

## Answers to the identity pages' open questions

4. "Builders launch their own." No source in the repo. Removed.
5. "Share" and "Don't share": true (`js/broker/broker.js`, the consent box). "A yes lasts for that tab and that identity only": true per the broker header. "The server checks your signature, and nothing more": not provable, because the account page also publishes the identity to the mesh directory after sign-in. It now reads "It checks your signature."
6. "Your key never leaves your device": true for the file and for opening it. With "Keep me signed in" the browser stores the identity locked under a key the page cannot copy out, and the bundle says a harmful script could sign until it expires. The claim holds. The safe page keeps the "Only this tab" advice.
7. `.auth.fxn` and the Emergency Kit: the create panel wrote version 9 files named `.auth.flx`. `docs/FLX_FORMAT_EXTENSIONS_v0.md` section 3 lists "the create panel in defxn" among writers that should write `.auth.fxn`. It now does. The Emergency Kit belongs to the version 10 file. `js/admin/vendor/auth-kit-create.js` still makes version 9, so a person who creates a file here never gets an Emergency Kit. The safe page now says that.
9. The 3D labels: "Sign in the browser" became "Sign in on your device". "Read your signed records" for resolvers describes a rulebook that reads records. Kept.

## What the browser session must change

1. Rename to "FXN Browser" in `package.json` (`name`, `description`), `electron-builder.config.js` (`productName`, `appId`, artifact names), `CLAUDE.md`, `README.md`, `ark://home` titles and every `ARK Browser` string in `src/`. The `userData` folder name changes with the product name and orphans the profile unless migrated.

3. Vendor comment and account menu say `.auth.flx` in `src/renderer/renderer.js`. Update to `.auth.fxn`.
4. Publish a download address, then set `DOWNLOAD.APP.BROWSER.URL` on the site. Until then the page is right to say none exists.
5. Windows and Linux targets, if they are planned. The site says only macOS is built.
6. `flux/defxn-browser-mobile`: the name "DEFXN Browser" in both apps.
